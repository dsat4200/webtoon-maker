# Mask-wand results — 2026-09-26

The default connected selection improved from **58.475 seconds to 4.541
seconds**, approximately **12.9× faster**, with identical mask tiles and finished
pixels. The bottleneck was repeated rendering of artwork for each reference
tile. Finding connected pixels and committing the mask required only about
40 milliseconds.

The implementation now skips artwork excluded by the inherited painter clip,
reuses exact effect outputs and setup within existing bounded caches, and keeps
reference requests inside the document. Sampling remains full resolution.
Two persisted controls expose the requested choices: **Connected** defaults on;
**Ignore other layers** defaults off and samples the selected object/layer when
enabled.

| Connected | Ignore other layers | Selection | Click through first redraw | Reference tiles |
|---|---|---:|---:|---:|
| On | Off — default | 4.541 s | 4.717 s | 14 |
| On | On | 0.671 s | 0.859 s | 14 |
| Off | Off | 20.494 s | 21.392 s | 1,075 |
| Off | On | 4.176 s | 4.364 s | 1,075 |

With Connected off, both cases scan the entire 1080×54896 document; neither is
restricted to the viewport or selected image bounds. Both select matching
disconnected regions, producing 20 mask tiles instead of the connected cases'
14. Ignoring other layers changes which artwork is sampled, including areas
covered by the speech bubble.

These are synchronous operations. The default first selection still has a
noticeable pause, and scanning every layer across the full chapter remains
slow. A warm repeat of the same connected default selection took **0.637
seconds** and did not change any mask pixels or add an undo entry. That run's
first selection took 4.015 seconds; the table retains the first authoritative
4.541-second reading instead of choosing the faster repeat run.

## Reproducer and scope

`tests/benchmark_mask_wand.py` sends a real Qt mouse click through normal tool
dispatch in a hidden native OpenGL Canvas. It measures the selection handler
and following paint separately, after the initial view has settled. It excludes
application startup and MainWindow ancillary refresh. Measurements are single
local runs, not physical device-to-display latency or a statistical guarantee.

The fixture is the latest saved `slam.png`, object
`d05523e0b3084570abefb49981eafe2a`: a 1280×1789 Blender image with its actual saved
6×4 mesh deformation. The screenshot's unsaved HSL/mask setup was absent from
the saved project, so the harness adds an in-memory HSL modifier with hue +30°
and an initially empty intensity mask. It preserves the complete saved scene
and clicks cyan document coordinate (100, 19600), tolerance 16. Camera center
is (540, 19750), scale .6, zero rotation, in a 1000×950 canvas. The native
before image visibly matches the supplied character/shoe/speech-bubble scene.

The chapter and all its local assets were copied to an isolated directory:
5,106 files, 167,930,128 bytes. Every copied hash matched the original before
and after copying. The original was read only. A verified 125-file pre-fix
Python source snapshot supplies the baseline. No project is saved, no live
editor is manipulated, and no MainWindow, broker or Blender connection is
instantiated. Settings and all generated artifacts stay isolated.

Diagnostic profiles and intermediate candidates are preserved separately.
They established that reference rendering consumed over 99.9% of the original
selection time, and then identified repeated outline outputs after clipping
was corrected. They are provenance, not the final timing comparison.
